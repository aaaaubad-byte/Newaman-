# AMAN — Implementation Changelog

## 2026-09-20 — Live contract correction

تمت مراجعة المستودع والنسخة الحية من مشروع Supabase `ilhgwludktlktzwxryhs` مباشرة بدل الاعتماد على تقرير التدقيق وحده. أظهرت المراجعة أن سلسلة migrations السابقة مطبقة جزئيًا، وأن بعض نقاط التقرير لم تعد تصف الحالة الحالية، بينما بقيت فجوات فعلية في عقد الحماية والقراءة التاريخية.

أضيفت migration باسم `202609202100_correct_live_contract_gaps.sql`. تمنع migration تقديم طلب حماية جديد لرقم لديه حماية سارية، مع الإبقاء على السماح بإضافة الرقم نفسه إلى قوائم عملاء متعددين. كما أضافت `logo_url` و`is_visible_to_customer` إلى شركات الاتصالات، وأنشأت فهرسًا لدعم فصل التفعيل الداخلي عن الظهور للعميل.

أعيد بناء View `customer_my_protections` ليعيد لقطات السعر والمدة والعملة المحفوظة في سجل الحماية بدل إجبار التطبيق على الرجوع إلى قيم الباقة الحالية. طُبقت migration بنجاح على مشروع Supabase الحي، وسُجلت باسم `correct_live_contract_gaps`.

تم تعديل Android ليقرأ `price_snapshot` و`duration_days_snapshot` و`currency_snapshot` من طلب الحماية قبل أي fallback قديم، وليقرأ حقول لقطات الحماية من View العميل. كما أضيفت حقول وصف الباقة وظهور الباقة وظهور الشركة وشعارها إلى نماذج التطبيق، وأصبح كتالوج العميل يستبعد الشركات والباقات غير الظاهرة له.

## التحقق

أكدت قاعدة البيانات وجود migration الجديدة، وحقول ظهور الشركة، وحقول اللقطات في View العميل، ووجود الحارس `NUMBER_ALREADY_PROTECTED` داخل دالة `submit_protection_request`. مرّ `git diff --check` دون أخطاء.

لم يُنفذ بناء Android كامل في هذه المرحلة لأن بيئة التنفيذ لا تحتوي Android SDK، وهو عائق بيئي مستقل وليس نتيجة فشل Kotlin مثبت.

## العوائق المتبقية

لا يزال دفع commit إلى GitHub غير ممكن من هذه الجلسة لأن رمز GitHub المحفوظ غير صالح ويحتاج إلى إعادة مصادقة. كما يلزم تشغيل اختبارات Android بعد توفير Android SDK، واختبار المسارات المصرح بها بمستخدمين تجريبيين داخل Supabase بدل تنفيذ عمليات بيانات حقيقية على حسابات المستخدمين.
