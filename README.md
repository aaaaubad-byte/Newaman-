# AMAN | أمان — Android

تطبيق أمان لإدارة أرقام العملاء، طلبات الحماية، المهام، شركات الاتصالات، الباقات، وسائل الدفع، وتصنيفات المهام. التطبيق مبني باستخدام Kotlin وJetpack Compose وMaterial 3، ويعتمد على Supabase كمصدر البيانات الوحيد.

## محتويات المشروع

- `app/`: كود تطبيق Android وموارده واختباراته.
- `gradle/`: Gradle Wrapper المطلوب للبناء المتكرر بنفس الإصدار.
- `DATABASE_SETUP_NEW_PROJECT.sql`: ملف SQL الموحد والأخير لإنشاء قاعدة بيانات Supabase جديدة.
- `supabase.local.properties.example`: نموذج إعداد الاتصال المحلي، ولا يحتوي على مفاتيح فعلية.
- `README.md`: تعليمات الإعداد والبناء والاختبار.

## المتطلبات

يتطلب المشروع ما يلي:

- Android Studio حديث يدعم Kotlin وJetpack Compose.
- JDK 21.
- Android SDK Platform 36.1 وBuild Tools 36.0.0 أو إصدار متوافق.
- مشروع Supabase جديد أو مُعد مسبقًا.
- اتصال إنترنت أثناء مزامنة Gradle وأثناء تشغيل التطبيق.

يمكن استخدام Gradle Wrapper المرفق بدل تثبيت Gradle يدويًا. على Linux وmacOS استخدم `./gradlew`، وعلى Windows استخدم `gradlew.bat`.

## 1. إعداد قاعدة بيانات Supabase

1. أنشئ مشروعًا جديدًا في Supabase أو استخدم مشروعًا فارغًا.
2. افتح **SQL Editor** في المشروع.
3. افتح الملف `DATABASE_SETUP_NEW_PROJECT.sql` وانسخ محتواه كاملًا.
4. نفّذ المحتوى مرة واحدة في SQL Editor وانتظر اكتمال التنفيذ دون أخطاء.
5. أنشئ حساب المدير من **Authentication → Users** باستخدام البريد وكلمة المرور.
6. استخدم معرّف المستخدم UUID الذي أنشأه Supabase لتنفيذ ترقية المدير في الجزء المخصص لذلك داخل ملف SQL، أو نفّذ أمر الترقية الذي يحدده الملف بعد إنشاء المستخدم.
7. لا تضع مفتاح `service_role` أو `sb_secret` داخل التطبيق أو ملفات المشروع. استخدم المفتاح العام `anon` أو `publishable` فقط.

> ملف SQL مخصص لمشروع جديد. لا تعِد تشغيله فوق قاعدة تحتوي على جداول وEnums ودوال باسم AMAN إلا بعد أخذ نسخة احتياطية ومراجعة التعارضات.

## 2. إعداد اتصال التطبيق محليًا

من مجلد المشروع انسخ نموذج الإعداد:

```bash
cp supabase.local.properties.example supabase.local.properties
```

ثم عدّل الملف المحلي وضع القيم التالية:

```properties
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_ANON_KEY=<anon-or-publishable-key>
```

يجب أن يكون `SUPABASE_URL` هو جذر مشروع Supabase فقط، ولا يجوز أن ينتهي بـ `/rest/v1/` أو أي مسار آخر.

ملف `supabase.local.properties` مستبعد من Git وملف ZIP النهائي عمدًا. بدائل CI المدعومة هي خصائص Gradle أو متغيرات البيئة بالاسمين `SUPABASE_URL` و`SUPABASE_ANON_KEY`.

## 3. فتح المشروع وتشغيله

افتح مجلد المشروع الذي يحتوي على `settings.gradle.kts` في Android Studio، ثم انتظر انتهاء مزامنة Gradle. بعد إعداد ملف الاتصال، شغّل التطبيق على جهاز Android أو محاكي يعمل بإصدار Android 7.0 (API 24) أو أحدث.

يمكن البناء من الطرفية:

```bash
./gradlew assembleDebug
```

ينتج ملف APK في:

```text
app/build/outputs/apk/debug/app-debug.apk
```

لبناء نسخة Release استخدم:

```bash
./gradlew assembleRelease
```

نسخة Release الناتجة غير موقعة بتوقيع متجر Play ما لم تُضف إعدادات توقيع خاصة ببيئة الإصدار. لا تضع ملفات keystore أو كلمات مرور التوقيع داخل المستودع.

## 4. الاختبارات والتحقق

لتشغيل الاختبارات المحلية:

```bash
./gradlew test
```

ولتجميع فحوصات المشروع:

```bash
./gradlew check
```

قبل بناء APK نهائي، تحقق من الآتي:

- ملف `supabase.local.properties` موجود محليًا أو أن متغيرات البيئة مضبوطة.
- رابط Supabase ومفتاحه من المشروع نفسه.
- خدمة Auth تستجيب بنجاح.
- تم تنفيذ ملف SQL كاملًا في المشروع الصحيح.
- تم إنشاء مستخدم مدير وترقيته، ثم اختبار تسجيل الدخول كمدير وعميل.
- لا يظهر مفتاح `service_role` أو `sb_secret` في أي ملف أو BuildConfig.

## 5. سلوك البيانات والأمان

يعتمد التطبيق على Supabase كمصدر البيانات، ولا يقوم بإنشاء تحديثات محلية وهمية بدل البيانات البعيدة. تتم حماية العمليات من خلال Auth وRLS وRPC المعرفة في ملف SQL.

المفتاح العام `anon` أو `publishable` ليس سرًا خادميًا، لكنه لا يمنح صلاحيات تجاوز RLS. لذلك يجب ضبط سياسات RLS والمنح والدوال في Supabase كما يحددها ملف `DATABASE_SETUP_NEW_PROJECT.sql`.

لا تضمّن الملفات التالية في المستودع أو في أرشيف مشاركة المشروع:

```text
supabase.local.properties
local.properties
*.keystore
*.jks
```

ولا تستخدم أبدًا داخل تطبيق Android:

```text
service_role
sb_secret
كلمة مرور قاعدة البيانات
```

## 6. الملفات المستبعدة من أرشيف المصدر

يُستبعد من الأرشيف كل ما يُعاد توليده أو لا يلزم لبناء المشروع، مثل `build/` و`app/build/` و`.gradle/` وملفات APK وملفات الإعداد المحلية. كما تُستبعد نسخ SQL القديمة والتقارير المرحلية، ويُرفق ملف SQL الموحد الأخير فقط.

## الترخيص والملاحظات

هذا الأرشيف هو نسخة مصدر قابلة لإعادة البناء. يجب إنشاء نسخة احتياطية من قاعدة Supabase قبل أي تغيير على مخطط قاعدة بيانات موجود، ويجب إدارة مفاتيح الإنتاج خارج ملفات المصدر.
